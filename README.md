# Soyuz-Pribor Test Assignment — AI Product Copywriter

Небольшой CLI для подготовки русскоязычных карточек промышленной продукции по исходным фактам. Используются только стандартная библиотека Python и совместимый с OpenAI Chat Completions API. В проекте нет сторонних Python-зависимостей.

## Что делает

- Принимает JSON-объекты с названием, производителем, характеристиками и исходным описанием.
- Формирует SEO-заголовок длиной не более 70 символов, описание длиной 800–1200 символов, структурированные характеристики, 3–5 поисковых запросов и коммерческий блок для B2B-аудитории.
- Не должен дополнять входные сведения догадками. Ожидаемые, но отсутствующие характеристики помечаются строкой `данных нет`.
- Проверяет структуру и длины полей, обязательные характеристики и числовые значения в тексте до выдачи результата.
- Поддерживает демонстрационный режим `--demo`, который не вызывает языковую модель и явно помечает результат как демонстрационный.

## Требования и запуск

Требуется Python 3.10 или новее. Зависимости устанавливать не нужно.

```powershell
git clone https://github.com/catlsp/soyuz-pribor-test-assignment.git
cd soyuz-pribor-test-assignment
```

```powershell
python -m product_copywriter examples/inputs.json --demo --format json --output examples/results.json
python -m product_copywriter examples/inputs.json --demo --format markdown --output examples/results.md
```

В обычном режиме настройте переменные окружения и запустите без `--demo`:

```powershell
$env:OPENAI_API_KEY = "ваш-ключ"
# Необязательно: значения по умолчанию показаны в .env.example
$env:OPENAI_BASE_URL = "https://api.openai.com/v1"
$env:OPENAI_MODEL = "gpt-4.1-mini"
$env:OPENAI_TIMEOUT = "30"
python -m product_copywriter examples/inputs.json --format json --output examples/results.json
```

Файл `.env` сам по себе не загружается. Скопируйте `.env.example` при необходимости и передайте значения переменных среде запуска отдельно. Не добавляйте секретный ключ в репозиторий.

## Формат входа

Файл может содержать один JSON-объект или массив объектов. Обязательное поле — только `name`. Поля `manufacturer`, `specs` (объект) и `description` необязательны; пустая строка, пустой объект и `null` в значении характеристики означают, что сведения не предоставлены. `expected_fields` задаёт перечень характеристик, которые должны присутствовать в структурированном выходе. По умолчанию это `Диапазон измерений`, `Класс точности`, `Питание`, `Тип корпуса`, `Интерфейсы`.

```json
{
  "name": "Манометр технический",
  "manufacturer": "Манотомь",
  "specs": {"Диапазон измерений": "0–1,6 МПа", "Класс точности": "1,5"},
  "description": "Прибор предназначен для измерения избыточного давления.",
  "expected_fields": ["Диапазон измерений", "Класс точности"]
}
```

В `examples/inputs.json` первый объект основан на предоставленном фрагменте PDF: манометр показывающий DM 02, производитель «Манотомь» (0–1,6 МПа, класс 1,5, G1/2, корпус 100 мм). Второй объект — явно помеченный синтетический неполный пример, а не второй товар из исходного задания.

Для отсутствующей характеристики результат содержит `"данных нет"`, а её название — в `missing_fields`. Неизвестные значения нельзя выдавать за установленные факты. Локальная проверка числовых значений — лишь эвристика и не гарантирует, что все утверждения семантически подтверждены или что единицы измерения и смысл параметров сохранены правильно. Проверьте сгенерированный текст и характеристики по первичной документации перед публикацией.

## Формат результата

JSON-результат содержит `seo_title`, `description`, `specs` (массив объектов `name`/`value`), `queries`, `commercial_block`, `missing_fields` и `mode`. `mode` различает результат языковой модели и демонстрационный результат. Markdown-режим представляет те же данные в читаемом виде.

Готовые демонстрационные результаты: [JSON](examples/results.json) и [Markdown](examples/results.md). Реальные запросы к LLM при подготовке сдачи не выполнялись; API-клиент проверен тестами с подменённым транспортом.
