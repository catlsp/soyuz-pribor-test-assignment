# Проверки API и примеров

## Текущая версия

2026-11-02 пользователь выполнил реальную генерацию текущей версии без `--demo`. Настройки: `OPENAI_BASE_URL=https://cheapvibecode.ru/v1`, `OPENAI_MODEL=gpt-6-luna`, `OPENAI_TIMEOUT=120`. API-ключ передан через окружение и не включён в репозиторий.

Результат программы сохранён без ручного изменения содержимого: [JSON](../examples/results.llm.checked.json), [Markdown](../examples/results.llm.checked.md). Обе карточки имеют режим `LLM`.

| Пример | SEO-заголовок, символов | Описание, символов | Поисковые запросы |
|---|---|---|---|
| Манометр DM 02 | 44 | 838 | 4 |
| Неполный синтетический датчик | 68 | 851 | 4 |

Проверены структура, длины, число запросов, полное совпадение характеристик и пропусков с нормализованным входом. Каждая фраза описания совпадает с фрагментом разрешённого каталога; заголовки, запросы и коммерческий блок также входят в каталог. Во втором примере отдельно отмечены отсутствующие производитель и описание. Автоматические тесты дополнительно проверяют API-транспорт с подменённым ответом и не требуют сети.

Для повторения задайте те же переменные окружения и выполните:

```powershell
python -m product_copywriter examples/inputs.json --format json --output results.llm.checked.json
```

На компьютере пользователя вместо `python` может использоваться `& $pythonExe`, если в этой переменной задан путь к интерпретатору. При повторном вызове модель может выбрать другой план; проверка каталога и ограничений остаётся обязательной. Сохранённый успешный прогон не гарантирует будущую доступность модели у провайдера.

## Архив прежнего свободнотекстового прогона

Файлы `examples/results.llm.raw.json`, `examples/results.llm.json` и `examples/results.llm.md` сохранены для прозрачности предыдущей версии, в которой модель генерировала прозу. Тогда пользователь подтвердил реальный вызов через `https://cheapvibecode.ru/v1` с моделью `gpt-6-luna`; описания имели длину 1011 и 936 символов. Этот исторический результат не проверяет текущий плановый формат и не должен представляться как результат работы актуального рендерера.

В необработанном описании манометра прежняя модель добавила неподтверждённые качественные утверждения: о чтении показаний по шкале, работе без сложных средств отображения и поставке в исполнении производителя. Простая проверка чисел не обнаружила эти утверждения. Отредактированные JSON и Markdown сохранены как отдельный пример ручной правки, а не как автоматический результат программы. Это одна из причин перейти к плану с ограниченными идентификаторами.

## Примеры без API

Актуальные демонстрационные результаты находятся в `examples/results.json` и `examples/results.md`. Они создаются с `--demo`, используют тот же рендерер и маркируются `DEMO — не LLM`. Эти файлы показывают формат и поведение при отсутствии источников, но не подтверждают доступность модели или сетевую интеграцию.
