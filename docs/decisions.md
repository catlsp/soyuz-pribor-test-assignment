# Проектные решения и ограничения

## Опора на исходные данные

Технические значения в карточке берутся из переданных полей товара. Модель не пишет описание свободным текстом: она возвращает план с идентификаторами фактов, советов, заголовка, поисковых фраз и коммерческого блока. Программа проверяет идентификаторы и собирает итог из разрешённых значений каталога. Реализация находится в [grounding.py](../product_copywriter/grounding.py), а структура ответа модели описана в [prompts.py](../product_copywriter/prompts.py).

Характеристики и список пропусков формируются отдельно от плана модели. Для ожидаемого отсутствующего поля выводится `данных нет`; имя включается в `missing_fields`. Пустые или `null` значения также считаются отсутствующими. Полный список исходных характеристик сохраняется в структурированном выходе, даже если текстовый лимит не позволяет включить каждую из них в описание.

Планировщик может выбирать порядок фактов и готовых нейтральных советов, но не создавать собственные технические утверждения. SEO-заголовок, поисковые запросы и коммерческий блок также выбираются из ограниченного каталога вариантов. При отсутствии достаточного описания назначения коммерческий текст говорит об уточнении задачи, а не приписывает товару отрасль или применение.

## Формат и проверка

Ограничения соответствуют заданию: SEO-заголовок до 70 символов, описание 800–1200 символов, 3–5 поисковых фраз и коммерческий блок с аудиторией/задачей или явным указанием, что их нужно уточнить. JSON-объект проверяется по схеме до вывода. Технические характеристики являются объектами `name`/`value`; отсутствующие значения и производитель/описание перечисляются в `missing_fields`.

План запрашивается через Chat Completions в режиме `json_object`, а не Structured Outputs. Для ошибки плана предусмотрена одна повторная генерация с замечанием валидатора. Каждая генерация может выполнить до трёх HTTP-попыток при временных ошибках, то есть верхняя граница — до шести запросов на товар. Ответы об ошибке, пустом теле или недопустимом JSON приводят к понятной ошибке CLI без печати ключа.

## Промпты и устойчивость к входному тексту

Системный промпт задаёт формат плана и запрещает воспринимать текст товара как инструкции. Пользовательский промпт передаёт товар как JSON и просит опираться на каталог разрешённых вариантов. Даже при некорректном или враждебном плане рендерер принимает только известные идентификаторы; неразрешённый свободный текст не становится содержимым карточки. Проверки такого поведения находятся в `tests/`.

## Ключи и API

LLM-режим использует OpenAI-совместимый Chat Completions API. Переменные окружения: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` и `OPENAI_TIMEOUT`. Значения по умолчанию для адреса и модели — `https://api.openai.com/v1` и `gpt-4.1-mini`; `.env.example` показывает формат. Приложение не загружает `.env` автоматически. Endpoint должен использовать HTTPS, кроме локального HTTP для тестирования.

Без ключа доступен `--demo`: он не обращается к сети, использует тот же рендерер и явно маркирует режим. Тесты подменяют транспорт и не требуют реального API.

## Известные ограничения и компромиссы

Рендеринг из готовых фраз ограничивает стилистическое разнообразие и может звучать повторно или сдержанно, особенно при скудных входных данных. Это сознательный компромисс ради проверяемого происхождения утверждений. Механизм устанавливает, откуда взят текст, но не подтверждает, что исходные сведения истинны, актуальны или соответствуют нужной модификации товара. Название и производитель также могут быть ошибочными во входе. Перед публикацией нужен человек, который сверит данные с документацией.

Входы демонстрируют один манометр по фрагменту задания и один синтетический неполный датчик. Полные сведения о втором назначенном товаре не предоставлены, поэтому синтетический пример не выдаётся за его карточку.

## Возможные улучшения

- Добавить ссылки на первичные источники по каждому факту и хранить происхождение полей.
- Улучшить тестовые сценарии на неоднозначные названия, длинные характеристики и разные категории приборов.
- Предусмотреть выбор тональности из небольшого заранее проверенного набора без свободного добавления фактов.
