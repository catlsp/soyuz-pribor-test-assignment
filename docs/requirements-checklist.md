# Сверка с требованиями задания

Таблица связывает требования PDF с реализацией и примерами. ТЗ предусматривает два товара, но PDF содержит только пример одного, а пользователь подтвердил отсутствие отдельных исходных данных. Поэтому второй входной объект синтетический и не считается карточкой второго реального товара.

| Требование | Где выполнено / как проверить | Статус и оговорки |
|---|---|---|
| Принимать данные JSON или через веб-форму | `product_copywriter/__main__.py`, `README.md`, `tests/test_cli.py` | Реализован разрешённый ТЗ вариант JSON: один объект или непустой массив. Веб-форма не требуется. |
| Передавать данные в LLM через API и формировать черновик | `product_copywriter/service.py`, `prompts.py`, `grounding.py`, `docs/live-check.md` | Текущая версия проверена реальным вызовом `gpt-6-luna` через CheapVibeCode. Модель выбирает редакторский план по исходным фактам, программа собирает карточку. |
| Возвращать удобный для копирования результат | `product_copywriter/formatting.py`, `__main__.py` | JSON или Markdown в stdout либо файл; пакетная запись атомарна. |
| Формировать SEO-заголовок до 70 символов | `product_copywriter/grounding.py` (каталог заголовков и сборка), `product_copywriter/models.py` (валидация), `tests/` | Реализовано и покрыто автоматическими проверками. |
| Формировать описание 800–1200 символов | `product_copywriter/grounding.py`, `product_copywriter/models.py`, `tests/` | Проверяется для обоих режимов. Все характеристики остаются в структурированном блоке, даже если не все помещаются в прозу. |
| Выводить структурированные характеристики | `product_copywriter/models.py`, `product_copywriter/formatting.py`, `examples/results.json` | Значения берутся из ввода; отсутствующие обозначаются `данных нет` и отражаются в `missing_fields`. Истинность исходных значений приложением не проверяется. |
| Предложить 3–5 поисковых запросов | `product_copywriter/grounding.py`, `product_copywriter/models.py`, `examples/results.json` | Варианты выбираются из каталога, а не генерируются свободной прозой. |
| Добавить коммерческий блок с аудиторией и задачей | `product_copywriter/grounding.py`, `examples/results.json` | Коммерческая аудитория ограничена ролью закупки/подбора. Если задача не подтверждена описанием, результат просит уточнить назначение. |
| Не выдумывать технические факты | `product_copywriter/prompts.py`, `product_copywriter/grounding.py`, `tests/` | Модель возвращает только план с идентификаторами разрешённых значений. Это подтверждает происхождение текста, но не правильность входных сведений. |
| Указывать отсутствующую информацию | `product_copywriter/models.py`, `examples/inputs.json`, `examples/results.json` | Отсутствующие характеристики показаны как `данных нет`; имя поля помещается в `missing_fields`. Пустые manufacturer/description тоже помечаются. |
| Обрабатывать API-ошибки, пустые поля и некорректный входной JSON | `product_copywriter/service.py`, `models.py`, `__main__.py`, `tests/` | Проверены неверный входной JSON, пропуски и null, некорректный ответ модели, 401/429, таймаут и обрыв соединения. Ошибки не раскрывают ключ. Реальный вызов текущей версии успешен. |
| Не хранить API-ключ в репозитории | `.env.example`, `.gitignore`, `README.md` | Используется `OPENAI_API_KEY` из среды; `.env` не загружается автоматически и исключён из Git. |
| Документировать запуск, промпты, ограничения и улучшения | `README.md`, `product_copywriter/prompts.py`, `docs/decisions.md` | Запуск без ключа доступен через `--demo`; LLM-запуск требует ключа и доступного совместимого API. |
| Предоставить примеры результатов | `examples/results.llm.checked.json`, `examples/results.llm.checked.md`, `examples/results.json` | Актуальные результаты реального API-вызова и отдельный демо-режим. Прежние свободнотекстовые ответы помечены как архив. |
| Обработать два назначенных товара | `examples/inputs.json`, `docs/decisions.md` | Частично: данных для второго реального изделия нет. Синтетический пример не подменяет его; для завершения нужны исходные сведения второго товара. |
| Использовать Python или JavaScript/TypeScript; локальный MVP | `pyproject.toml`, `product_copywriter/`, `README.md` | Python 3.10+, стандартная библиотека. CMS, сервер, БД и деплой не нужны по ТЗ. |
| Сдать Git-репозиторий, README и сопроводительное сообщение | `README.md`, `docs/submission.md` | Публичный репозиторий `https://github.com/catlsp/soyuz-pribor-test-assignment`; сообщение описывает решения, проверку и ограничение по исходным данным. |
| Запись экрана или скриншот при необходимости | `examples/results.llm.checked.md`, `docs/live-check.md` | Необязательный пункт. Результаты доступны для просмотра напрямую в репозитории. |

Для ручной проверки после получения данных второго товара замените синтетическую запись в `examples/inputs.json`, выполните команду из README и сверьте карточку с первичной документацией изделия.
